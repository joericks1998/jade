# `src/typechecker/infer/`: whole-program static types

## What this subtree is

This is Jade 2.0's type checker. It works out one concrete type for every value in a program, with no annotations, so the backend can compile an int to a register and a struct to a fixed layout with no type tags. It also decides which programs Jade 2.0 accepts. The rules it enforces are the decisions in [`design/v2-static-values.md`](../../../../design/v2-static-values.md); read that first.

It runs on the whole merged program: after the per-file pass in `resolve.rs`, after the import pass inlines every module, and after struct defaults are filled. It reads the parser's tree, `frontend::ast`, as that pass left it, and keeps every type in its own table rather than on the nodes. Its answer is the input to the rest of the build: [`src/mir/`](../../mir/README.md) lowers it into typed code. A program it rejects neither builds nor passes `jade check`.

It reports every type error. Until 2.0.6 the per-file pass gave each node a type of its own and refused some mismatches itself, such as `1 + "a"`, `if 1` or `prompt p = 42`; the checker raises each of those in its own words, and a pipe stage bound to a value that is not a function in the pipe's words, `'|>' needs a function on its right`, by recording which calls are a pipe's stages.

## Why it was built

The v1 checker, the per-file pass of its day, was one forward pass with no type variables. A function's parameters are always `Unknown`, a call never looks at its arguments, and `Unknown` spreads into everything it touches. That was enough to pick `AddInt` over a dynamic add where it could, and left everything else to tags checked while the program ran. A backend with no tags needs every type known, so the inference had to change shape rather than get better at the edges.

## How it works

*A function is checked once per set of argument types.* `add(1, 2)` checks `add`'s body with both parameters `int`; `add(1.5, 2.0)` checks it again with both `float`. Each distinct set of argument types is an *instance*, keyed by `InstKey`, and the backend compiles one copy per instance. A method is checked per receiver type the same way, so an inherited method gets a copy for each child that calls it. A function nobody calls is never checked, and never compiled.

*Every value lives in a slot, and slots only widen.* `ty::Store` holds them. A variable, an array element, a dict value and a struct field are each a slot, so `let xs = []` makes an array whose element slot is empty, and a later `xs.push(1)` fills it. Two types meet through `Store::join`: `int` and `int` give `int`, a type and `nil` give an optional, two structs give their nearest common parent, and anything else is a mismatch. Joining never narrows a slot.

*The checker repeats its pass until nothing changes.* Types flow in every direction, so one walk cannot get them right. `run` checks `main` and every instance it reaches, over and over, until a whole pass leaves `Store::version` unchanged. Errors are collected only on the last pass, once every type has settled; a type that is merely not known yet on an early pass is not an error. A slot nothing ever constrained is `nil` by then, which is what an empty array nobody fills holds.

*Slots are cached by syntax node address.* Each instance keeps a map from the address of the node that made a slot to the slot, so a second pass reuses the first pass's slots instead of making new ones. That is what makes "nothing changed" mean the types have settled. The program outlives the checker, so an address is a stable identity for the whole run. Anything that makes a slot inside a body must go through `Checker::slot` for this reason; a `store.fresh()` there makes a new slot every pass and the passes never settle.

*Functions as values.* A named function or builtin used as a value has the type `Ty::Func`, which is not yet given argument types. Calling one through a variable checks it at that call's types, the way calling it by name does. When two different functions meet in one place, such as an array literal of functions, they join into one `Ty::Fn` with shared parameter and return slots, and `Store::fn_members` remembers which functions flowed in. Once the parameter types settle, `settle_fn_members` checks each member at them. Closures and bound methods were removed in 2.0.1; a method used without a call is refused with a message saying to call it.

*Visibility.* A class member is private unless its class marks it `@public`. `check_visible` refuses reading or setting a private field, or calling a private method, from code outside the class that owns it and its descendants. The code being checked belongs to a class when it is one of that class's methods, or its constructor, the function the parser names `Class::new`. Built-in structs such as `RuntimeError` have only public members. A call to a method the class declares but nothing defines is refused here, at the call, so a file can declare methods its importers define.

*`toDict`'s value type comes from use.* `toDict(text)` returns a dict whose value type is a slot of its own, recorded in `Checker::todict_slots`, so how the program uses the dict decides what it holds, per part 2 of `design/v2-simplify.md`: `d["a"] + 1` makes it an int. Indexing such a slot while it is empty makes it a dict when the index is a str and an array when it is an int, and a method only dicts or only arrays have does the same; the inner slot is recorded too, so nested levels follow the same rule. A converter accepts a str, so `toInt(d["k"])` fills nothing. When the passes settle, after any waiting literal has taken its type, `Checker::run` makes every recorded slot still empty a str and runs the passes again, so a dict nothing settles is a dict of strings. On the last pass the call refuses a value type the reader cannot build, such as an optional. Passed as a value, `texts.map(toDict)`, it reads a dict of strings. The code is at the end of `builtins.rs`.

*Narrowing.* Inside `if (x != nil) { … }`, and after `if (x == nil) { return }`, the variable is read as its non-optional type. Inside `if (x is Dog) { … }` it is read as a `Dog`. `&&` narrows its right side by its left.

*The std library written in Jade.* `std::path`, `std::time` and `std::math` are Jade source in `src/lib/`, merged into a program that uses them, so their functions are checked like the program's own, at the argument types each call gives. Three things apply to library code alone, which `is_library_fn` recognizes by its reserved namespace id.

- *A built-in type test.* `x is int`, `x is float`, `x is str` and the rest, `nil` among them, have one answer per instance, so an `if` on such a test, alone or joined by `and`, `or` and `not`, checks only the branch it takes (`static_test`). That is how `math.abs` returns an int for an int and a float for a float. On a pass before `x`'s type is known neither branch is checked. A test on a `T?` is asked while the program runs, and narrows `x` to `T` inside and to nil outside, so `std::path` reads a `str?` as the str it holds, as it always did.
- *Hooks.* A call to `__sys`, the hook package, is typed in `builtins.rs` from `SysFn::params` and `SysFn::result`, exactly: a float parameter refuses an int.
- *Errors are reported at the program's call.* `instantiate` records, for each library instance, where the program first called into library code and what it called, such as `path.join(int, int)`; an instance one library function makes for another takes its caller's. While a library instance is checked, `report` moves an error there and prefixes it: `in path.join(int, int): str() needs a str, got int; convert one with toString()`. An arity error at the call names the function as the program wrote it, `'math.pow' takes 2 arguments, got 3`. A type function that refuses its argument still gives its own type, so the error the program sees is the one at its cause rather than a later one it led to.

*Classes.* `Class(x)` views a value as a class it is or descends from; a class decorator on a `let` becomes one. `Parent::m(self, …)` inside a method resolves to that parent's version of `m`, with `self` put first by the type pass. A field's type decorator joins into its slot when classes are registered. Nothing calls a destructor, so `instantiate_drops` checks each constructed class's `drop` chain, its own then its ancestors', and `Typed::drops` hands the chains to the backend; calling `drop`, or giving it arguments, is refused. Narrowing lives beside the scopes rather than in them, so assigning the variable still reaches its real slot.

## What each file does

- *`mod.rs`* holds `check_program`, the `Checker`, registration of every top-level definition, the struct hierarchy and field slots, the pass loop, `instantiate`, and the `Typed` answer: every instance, the resolved type of every expression and every slot by instance and node address, what every call resolved to, and every struct's layout.
- *`members.rs`* checks the class rules that need what a program wrote rather than what the compiler filled in, so `aot` runs it before struct defaults are filled: a literal outside a class sets only public fields, a private field it leaves out needs a default or a constructor, a method defined outside its class is declared in the body, and no method is defined twice. It reads each literal's `given` list, the fields the source wrote.
- *`ty.rs`* holds `Ty`, `FnTy`, `FuncRef`, `SizedNum`, the seven sized number types each `Ty::Sized` names, and the `Store` of slots with `join`, `resolve`, the cycle check that refuses a type containing itself, and the common-ancestor walk that joins two structs. `Store::set` counts a change only when the slot's type, read through its slots, differs: before 2.0.8 an array parameter joined with three callers' arrays of ints was rewritten to each caller's element slot in turn, every pass, and the program never settled, which a library function such as `random.choice` would hit in any program that called it three times.
- *`check.rs`* checks statements and expressions inside one instance: scopes, narrowing, calls by name, by value and by method, operators, struct literals, fields and indexing, `join` and `wait`. A copy-with literal, `Full { ...base }`, reads each field it leaves out from the base when the base's class has it, and checks the field's declared default, kept in `Checker::default_exprs`, when it does not; MIR lowers the same default there. It holds the sized number rules of `design/v2-number-types.md`: both sides of an operator have one type, and a number literal takes the type it meets. `Checker::accept` joins a value into a slot and lets a literal take a sized slot's type; a literal meeting a slot nothing has filled waits in `pending_literals` until the passes settle, so `if (c) { return 0 } return b` with `b` a byte returns bytes, and `Checker::run` gives a slot still empty then the literal's own type. A side of `==` or `+` not known yet facing a string waits the same way, in `deferred_eq`, since a char compares with and joins a string: `for c in word() { out = out + c }` reads `c` as the char `word()`'s string gives once it settles, and makes it a string only if nothing does.
- *`builtins.rs`* holds the types of everything a program calls without writing it: the bare globals, including the type functions, which check, and the converters, which convert, `toDict` and the use-decided type of what it reads among them, with `long` and `double` read as `int` and `float` by `canonical`, the functions of the std packages the backend still writes, `string`, `array`, `dict` and `bytes`, the primitive methods, the hooks library code calls through `__sys`, whose argument mismatches are worded without the hook's name, since the message already names the library function the program called, and the built-in structs (`RuntimeError`, and one `Settled` struct per `join(…, settle = true)` site). Every other std package is Jade and typed from its bodies. `TimeParts`, `HttpResponse`, `HttpBytesResponse` and `ShOutput` were built-in structs until 2.0.8, when their packages became Jade and declared them as classes in `time.jde`, `http.jde` and `sh.jde`.
- *`tests.rs`* pins each rule with one program that checks and, where the rule refuses something, one that does not.

## Who uses it

*Used by:* `aot::compile` and `aot::would_build`, and `mir::lower_program`, which reads `Typed`. `cli/check.rs` reaches it through `would_build`, which is also how the `every_example_matches_its_expected_check_result` test judges every fixture.

*Depends on:* `frontend::ast` for the merged program it reads and its struct field definitions, and `builtins` for the package and primitive-method name lists.

## Gotchas

*A slot made inside a body must be cached.* See "Slots are cached by syntax node address" above. The symptom of getting it wrong is the error "the program's types never settle", on a program that has nothing recursive in it.

*`join` must not make a type contain itself.* An array pushed into itself would need an element type that is its own array type, and `resolve` would recurse until the stack ran out. `Store::occurs` refuses that on both paths `join` can fill a slot, and it compares a slot before following what the slot holds; following first looked past the slot itself once it had been defaulted to `nil`.

*Calls into Rust packages are typed from the package's own description.* `#[jade::export]` puts a record of each function's signature, in Jade's spelling, in the built library (`rustpkg/`), and `native.rs` reads each type, such as `[str]`, `uint32?` or `geo::Point`, into a `Ty`, a struct naming its class. `check_program_with` takes the signatures by `__native$<pkg>$<fn>`. Every signature is complete, so a call unifies each argument with its parameter through `accept`, which lets a number literal take a sized parameter's type as it does in an assignment, and the call has the declared result. Until 2.0.5 a native function could be undeclared, its result inferred from use; with every native call described by its library, that inference is gone.

*An `==` between a char and a string waits for its unknown side.* A char compares equal to the one-character string spelling it, so when one side of `==` or `!=` is a string or char and the other is not known yet, the checker does not make them one type on that pass: the unknown side may come from a call checked later, such as `let c = first(s)` where `first` returns a char, and forcing it to `str` first made the program fail. If the passes settle with such a side still unknown, `deferred_eq` turns on `force_eq` for one more pass, which joins the two sides as before.

*A function only C calls is still checked.* A named function passed where a function type is declared is checked at that type when its function type settles, and each pass keeps draining its worklist until settling adds nothing new. Otherwise the final pass would leave such a function out of the answer.
