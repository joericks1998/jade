Exceptions

Jade provides structured exception handling through three keywords: raise raises any value as an exception, try wraps a block that might raise, and catch handles the raised value by type or unconditionally.

Overview

An exception is any Jade value raised with the raise statement. The raised value can be a string, a struct instance, an integer, or any other runtime value. The most common pattern is to define a dedicated struct type to carry the exception payload, then raise an instance of that type. This lets catch arms match by type name and access the fields of the caught value.

A try/catch block wraps the statements that might raise. If the try body completes without raising, execution continues normally after the last catch arm and no catch arm runs. If a raise occurs, execution of the try body stops immediately and the runtime searches the catch arms in order, executing the first one that matches the raised value.

Built-in runtime errors — division by zero, type errors, undefined variable references, index out of bounds, and all other JadeError variants — are automatically wrapped in a synthetic RuntimeError struct with a single message field. A catch-all arm (catch e { … }) will catch these just as it catches user-raised exceptions, allowing programs to recover from runtime errors cleanly.

If no catch arm matches the raised value, the exception propagates outward to the nearest enclosing try/catch. If it reaches the top level without being caught, the program exits with an error message.

Syntax

raise

raise <expr>
  • <expr> — any expression. The evaluated value becomes the raised exception. Execution of the enclosing block stops immediately after raise.

try / catch

try {
    <body statements>
} catch <TypeName> <binding> {
    <arm statements>
} catch <binding> {
    <arm statements>
}
  • <body statements> — any sequence of statements that might raise.
  • <TypeName> — an optional struct type name. When present, this arm only matches exceptions that are instances of that struct type. When absent, the arm is a catch-all and matches any raised value.
  • <binding> — a name bound to the caught value inside the arm body. For typed arms, the bound value is the struct instance; for catch-all arms, it is whatever was raised.

Any number of typed catch arms may appear before the optional catch-all. Arms are tested in the order they are written; the first match wins and the rest are skipped. A catch-all arm should appear last because it matches everything.

Basic Examples

Raising and catching a string

fn risky() {
    raise "something went wrong"
}

try {
    risky()
} catch e {
    print(e)
}

risky raises a string. The catch-all arm binds the string to e and prints it. Output: something went wrong. Any Jade value can be raised, not just strings.

Typed catch with a struct exception

struct ValueError { message }

fn parse_age(n) {
    if n < 0 {
        raise ValueError { message: "age cannot be negative" }
    }
    return n
}

try {
    parse_age(-1)
} catch ValueError e {
    print(e.message)
}

Defining a dedicated exception struct lets catch arms match by type. Here catch ValueError e only runs when the raised value is a ValueError instance. The field e.message holds the error description. Output: age cannot be negative.

Catching a built-in runtime error

try {
    let x = 1 / 0
} catch e {
    print("caught runtime error")
}

Division by zero normally terminates the program. Inside a try block, built-in runtime errors are automatically wrapped in a RuntimeError struct with a message field. The catch-all arm binds this struct to e and the program continues. Output: caught runtime error.

Advanced Examples

Multiple typed catch arms — first match wins

struct NetworkError { code, message }
struct ValueError { message }

try {
    raise NetworkError { code: 503, message: "service unavailable" }
} catch ValueError e {
    print("wrong: value error")
} catch NetworkError e {
    print(e.code)
    print(e.message)
} catch e {
    print("wrong: catch-all")
}

Three arms are checked in order. The raised value is a NetworkError, so the first arm (catch ValueError) does not match. The second arm matches and runs, printing 503 then service unavailable. The catch-all is never reached.

Exception propagation through the call stack

struct ValueError { message }

fn inner() {
    raise ValueError { message: "deep error" }
}

fn outer() {
    inner()
}

try {
    outer()
} catch ValueError e {
    print(e.message)
}

When inner raises, execution unwinds through outer without any catch arm in either function. The exception propagates to the try/catch block at the call site, which catches it and prints deep error. Exceptions cross function boundaries automatically.

Nested try/catch — inner handles if it matches, outer handles if it does not

struct ValueError { message }
struct NetworkError { code, message }

try {
    try {
        raise ValueError { message: "inner error" }
    } catch NetworkError e {
        print("wrong: inner caught network error")
    }
} catch ValueError e {
    print(e.message)
}

The inner try/catch only handles NetworkError. Because a ValueError was raised and the inner arm does not match, the exception propagates to the outer try/catch, which catches it and prints inner error.

try body completes normally — catch never runs

try {
    let x = 1 + 1
    print(x)
} catch e {
    print("wrong: should not run")
}

When no exception is raised, the try body executes fully and no catch arm runs. Output: 2.

Type Rules

catch TypeName e — typed arm Raised value must be Value::Struct with type_name == TypeName Arm body executes; e bound to the struct instance eval.rs: Stmt::TryCatch — checks rc.borrow().type_name == type_name
catch e — catch-all arm Any raised value, including built-in runtime errors Arm body executes; e bound to the raised value eval.rs: None catch type always matches
Built-in runtime error inside try Any JadeError that is not Exception Wrapped as RuntimeError { message } struct; catchable by catch-all or catch RuntimeError e eval.rs: Err(other) arm in TryCatch handler
No catch arm matches Raised value does not match any typed arm Exception re-raised; propagates to nearest enclosing try eval.rs: re-raises JadeError::Exception after all arms are checked
Note: Typed catch arms only match struct values — they check the type_name field of the struct instance at runtime. Raising a plain string or integer and then catching with a typed arm will not match; use a catch-all arm to handle non-struct raises.

Any other JadeError inside try Built-in runtime error (division by zero, index out of bounds, etc.) occurs inside the try body try { let x = 1 / 0 } catch e { print(e.message) } — catches as RuntimeError

Interaction with Other Features

  • Structs: The most common pattern is to raise struct instances as typed exceptions. Define a dedicated struct for each exception category, include a message field (or any fields that carry diagnostic context), and raise an instance. Typed catch arms match by struct type name. See Structs.
  • Functions: Exceptions propagate through function call boundaries automatically. A raise inside a function unwinds the call stack until it reaches the nearest enclosing try/catch, regardless of how many function calls deep the raise occurs. See Functions.
  • Control flow: try/catch blocks can appear anywhere a statement is valid — inside if branches, inside while loop bodies, or at the top level. A return inside a try body exits the enclosing function normally without triggering any catch arm. See Control Flow.
  • Variables: The binding introduced by a catch arm (catch e { … }) is scoped to that arm's body. Variables declared with let inside a catch arm are not visible outside it. Use bare assignment to write back to a variable declared in an enclosing scope from inside a catch arm.
  • Raise anything: The raise keyword accepts any expression — strings, integers, booleans, struct instances. Typed catch arms only match struct instances; everything else can only be caught by a catch-all arm.

Implementation Notes

Note: When a raise statement executes, the evaluator stores the raised value in env.raised_exception and returns a Rust Err(JadeError::Exception). The TryCatch handler in eval.rs checks whether the error is a JadeError::Exception and retrieves the value from env.raised_exception. Other JadeError variants (division by zero, type error, etc.) are caught by the Err(other) arm and wrapped in a synthetic RuntimeError { message } struct so that catch arms can match and inspect them.
Note: Each catch arm body executes in its own child scope. The evaluator calls env.push_scope() before entering the arm, binds the exception value to the arm's binding name via env.define, and calls env.pop_scope() after the arm body completes. Variables declared with let inside a catch arm are not visible outside that arm.
Note: When no catch arm matches a raised exception, the evaluator re-raises it: it stores the value back in env.raised_exception and returns a new Err(JadeError::Exception). This propagates the exception upward through the Rust call stack to the next enclosing TryCatch handler, or to the top level where it produces an error message (eval.rs: end of Stmt::TryCatch arm).
Note: If a try body completes normally (returns Ok(ret)), the TryCatch handler immediately returns that result and no catch arm is consulted. A return statement inside a try body propagates normally and is not treated as an exception (eval.rs: Ok(ret) => return Ok(ret)).
