Functions

Jade functions are defined with fn, accept zero or more parameters, and return a value either with an explicit return statement or via implicit return (the last bare expression in the body). Functions are first-class values and can be passed to other functions or assigned to variables.

Overview

A function is a named, reusable block of statements. It is introduced with the fn keyword, followed by a name, a parenthesized parameter list, and a brace-delimited body. Calling a function evaluates its body in a new scope and returns a value.

There are two ways to return a value from a function:

  • Explicit return: return <expr> exits immediately and produces that value.
  • Implicit return: if the last statement in the body is a bare expression (no return keyword), that expression's value is returned automatically.

If execution reaches the end of the body without hitting a return statement and without a final bare expression, the function returns nil. A bare return with no expression also produces nil.

Functions are first-class values in Jade. A function definition binds the name to a fn value in the current environment, just like let binds a name to an integer or float. That value can be stored in a variable, passed as an argument, and called through any expression that evaluates to a function.

Syntax

Function Definition

fn <name>(<param>, <param>, ...) {
    <body statements>
    return <expr>
}
  • <name> — an identifier naming the function; binds it in the enclosing scope.
  • <param> — zero or more parameter names separated by commas; each becomes a local variable inside the body.
  • <body statements> — any sequence of statements. If the last statement is a bare expression, its value is returned implicitly.
  • return <expr> — exits immediately and produces the given value. A bare return produces nil.

Function Call

<expr>(<arg>, <arg>, ...)
  • <expr> — any expression that evaluates to a function value.
  • <arg> — zero or more argument expressions evaluated left-to-right in the caller's scope.

Basic Examples

A function with two parameters

fn add(a, b) {
    return a + b
}

let sum = add(3, 4)

add takes two parameters and returns their sum. Calling add(3, 4) evaluates the body with a = 3 and b = 4, producing 7.

Implicit return (last expression)

fn double(x) {
    x * 2
}

print(double(5))  // 10

The last statement is the bare expression x * 2. Because it is not a let, if, or other statement, its value is automatically returned. This is equivalent to writing return x * 2.

A function with no parameters

fn get_answer() {
    return 42
}

let answer = get_answer()

The empty parameter list () is required even when there are no parameters. The call get_answer() returns 42.

Chaining calls

fn square(x) {
    return x * x
}

let chained = add(square(2), square(3))

Call expressions can be nested. square(2) evaluates to 4, square(3) evaluates to 9, and add(4, 9) returns 13. Arguments are evaluated in the caller's scope before the call is made.

Using local variables inside a function

fn local_shadow(x) {
    let y = x * 2
    return y
}

let c = local_shadow(5)

Variables declared with let inside a function body are local to that call frame. y is created inside local_shadow and is not visible outside. The call returns 10.

Advanced Examples

Recursion — factorial

fn factorial(n) {
    if n == 0 {
        return 1
    }
    return n * factorial(n - 1)
}

let f5 = factorial(5)

Functions can call themselves. factorial(5) computes 5 * 4 * 3 * 2 * 1 = 120. The base case n == 0 returns 1 to stop the recursion. Mutual recursion — two functions that call each other — also works because function definitions are bound in the same environment before either is called.

First-class functions — higher-order functions

fn double(x) {
    return x * 2
}

fn apply(f, x) {
    return f(x)
}

fn compose(f, g, x) {
    return f(g(x))
}

let f = double
let a = f(5)
let b = apply(double, 6)
let d = compose(double, double, 3)

double is assigned to f, which can then be called as f(5). apply receives a function as its first argument and calls it with the second. compose applies g first, then passes the result to f. compose(double, double, 3) returns 12: double(3) = 6, then double(6) = 12.

Fibonacci — two recursive calls

fn fib(n) {
    if n <= 1 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

let fib10 = fib(10)

Each call to fib makes two recursive calls. fib(10) returns 55. The defining scope captured at function definition allows each nested call to resolve fib by name.

Interaction with Other Features

  • Control flow: if/else and while statements can appear inside a function body. A return inside a branch or loop body exits the enclosing function immediately. See Control Flow.
  • Arithmetic promotion: Return values participate in arithmetic just like any other value. If fn f() { return 1 } and you write f() + 0.5, the integer 1 is promoted to float and the result is 1.5.
  • Recursion: A function can call itself by name. The evaluator looks up the function name in the call frame's parent chain, which always includes the scope where the function was defined.
  • Variable bindings: The let statement can bind a function value: let f = double. The bound name is then callable. Reassigning through another let in the same scope creates a new binding; the original function object is not mutated.
  • Scope: Each call creates a child scope of the function's defining scope (not the calling scope). Variables declared at the top level are visible inside functions, but variables declared inside a function are not visible outside.

Closures

A closure is an anonymous function written inline using the |params| body syntax. It captures a snapshot of the variables visible at the point it is created, so it can reference those variables even when called later from a different scope.

Syntax

|<param>, <param>, ...| <expr>      // single-expression body
|<param>, <param>, ...| { <stmts> } // block body
|| <expr>                              // zero-parameter closure

Basic examples

// Single-expression body — implicitly returns the expression
let double = |x| x * 2
print(double(5))   // 10

// Multiple parameters
let add = |x, y| x + y
print(add(3, 4))   // 7

// Zero parameters
let greet = || "hello"
print(greet())   // hello

Capturing outer variables

All variables visible at closure creation are captured by copy. The closure carries its own snapshot — mutations inside the closure do not affect the outer scope, and reassigning the outer variable after closure creation has no effect on the closure. 

let multiplier = 3
let triple = |x| x * multiplier
print(triple(5))   // 15

Block body

let abs_val = |x| {
    if x < 0 {
        return -x
    }
    return x
}
print(abs_val(-7))   // 7
print(abs_val(4))    // 4

Closures as arguments

Closures are first-class values and can be passed to higher-order functions: 

fn apply(f, x) {
    return f(x)
}

let result = apply(|x| x * x, 6)   // 36
Note: The | symbol that opens a closure is only treated as a closure delimiter when it appears at the start of an expression (primary position). In all other positions it remains the bitwise OR operator. The empty-param form uses ||, which is distinct from the logical OR operator because || only appears as logical OR in an infix position, never at the start of an expression.

Implementation Notes

Note: Nested function definitions — a fn statement inside another function's body — are rejected at parse time with a NestedFunction error. The parser tracks fn_depth and increments it when entering a function body (parser.rs: parse_fn).
Note: Auto-semicolon insertion does insert a semicolon after a closing } at the end of a line. The parser handles } else { across lines by consuming any such semicolon before checking for else (parser.rs: parse_if; lexer.rs: is_line_terminator includes RBrace).
Note: Arguments are evaluated in the caller's scope before the call frame is created. This means argument expressions can reference names in the caller's environment, and side-effects from evaluating one argument (such as a function call that modifies no shared state) are visible to subsequent argument evaluations. (eval.rs: the argument loop runs against env, not call_env.)
Note: A function with no return statement, or one where control falls off the end of the body, returns integer 0. This is equivalent to a bare return (eval.rs: unwrap_or(Value::Int(0))).
