Control Flow

Jade provides two control flow constructs: if/else for conditional branching and while for repetition. Both require a bool condition.

Overview

The if statement tests a condition expression and executes the then block when the condition is true. An optional else block executes when the condition is false. If no else is provided and the condition is false, the statement does nothing.

The while statement repeatedly evaluates its condition and executes its body as long as the condition remains true. When the condition becomes false, execution continues with the statement after the closing }. If the condition is false on the first check, the body never executes.

Both constructs require the condition to evaluate to a bool value. Providing any other type — an int, float, or fn value — raises a TypeError. There is no implicit truthiness for non-boolean types.

Control flow statements can appear at the top level or inside function bodies. A return inside a branch or loop body exits the enclosing function. Using return outside of a function body raises a ReturnOutsideFunction error.

Syntax

if without else

if <condition> {
    <then statements>
}

if with else

if <condition> {
    <then statements>
} else {
    <else statements>
}
  • <condition> — any expression that produces a bool. Common sources: comparison operators (<, >, ==, etc.), logical operators (&&, ||, !), or a variable holding a bool value.
  • <then statements> — any sequence of statements to execute when the condition is true.
  • <else statements> — any sequence of statements to execute when the condition is false. May itself contain if/else to create chains.
Note: The else keyword must appear on the same line as the closing } of the then block, or on the next line. Because the lexer does not insert a semicolon after }, writing } else { on one line or splitting across lines both work correctly.

Basic Examples

Returning different values based on a condition

fn max(a, b) {
    if a > b {
        return a
    } else {
        return b
    }
}

let m1 = max(3, 7)
let m2 = max(10, 2)

max compares a and b and returns the larger. max(3, 7) takes the else branch and returns 7. max(10, 2) takes the if branch and returns 10.

if without else — early return pattern

fn clamp(x, lo, hi) {
    if x < lo {
        return lo
    }
    if x > hi {
        return hi
    }
    return x
}

let clamped_lo  = clamp(1, 5, 10)
let clamped_mid = clamp(7, 5, 10)
let clamped_hi  = clamp(15, 5, 10)

Multiple if statements without else create an early-exit chain. clamp(1, 5, 10) hits the first condition and returns 5. clamp(7, 5, 10) skips both conditions and falls through to return x, returning 7. clamp(15, 5, 10) hits the second condition and returns 10.

Boolean variable as condition

fn is_positive(x) {
    if x > 0 {
        return true
    } else {
        return false
    }
}

let pos = is_positive(5)
let neg = is_positive(-3)

The condition can be any expression that produces a bool. Here x > 0 evaluates to true or false, which the if statement tests. is_positive(5) returns true; is_positive(-3) returns false.

Advanced Examples

Nested if/else — sign function

fn sign(x) {
    if x > 0 {
        return 1
    } else {
        if x < 0 {
            return -1
        } else {
            return 0
        }
    }
}

let s1 = sign(10)
let s2 = sign(-5)
let s3 = sign(0)

The else branch itself contains another if/else, creating a three-way branch. sign(10) returns 1, sign(-5) returns -1, and sign(0) returns 0. Nesting depth is not bounded by the language.

Nested if — quadrant classification

fn quadrant(a, b) {
    if a > 0 {
        if b > 0 {
            return 1
        } else {
            return 4
        }
    } else {
        if b > 0 {
            return 2
        } else {
            return 3
        }
    }
}

let q1 = quadrant(1, 1)
let q2 = quadrant(-1, 1)
let q3 = quadrant(-1, -1)
let q4 = quadrant(1, -1)

Both the then and else branches contain their own if/else to inspect a second variable. quadrant(1, 1) returns 1 (positive a, positive b). quadrant(-1, 1) returns 2, and so on.

Error Conditions

Interaction with Other Features

  • Functions: if/else is typically used inside function bodies. A return inside a branch exits the entire enclosing function, not just the branch. See Functions.
  • Logical operators: The condition can use &&, ||, and ! to combine multiple boolean sub-expressions. All operands must be bool. See Operators.
  • Comparison operators: The most common source of bool conditions is comparison expressions: x > 0, a == b, n <= 1, etc. These produce bool values that the if statement can test directly.
  • Variable bindings: A let statement inside a branch creates a binding in the branch's own child scope. Variables declared inside a then or else block are not visible outside that block. Use bare assignment (x = expr) to update a variable declared in an enclosing scope from inside a branch.
  • Recursion: if/else is the standard way to express base cases in recursive functions. The condition tests for the stopping condition and the return inside exits the recursion at that call.

Implementation Notes

Note: The lexer does insert a semicolon after a closing } at the end of a line (RBrace is a line-terminator token in lexer.rs: is_line_terminator). The parser handles this by consuming any auto-inserted semicolon before checking for else (parser.rs: parse_if). This means } else { split across lines parses correctly.
Note: A return statement inside either the then or else block propagates upward through the block evaluator using Rust's Option<Value> return type. When eval_block returns Some(value), the caller propagates it immediately without executing any further statements in the enclosing block. This is how a return deep inside a branch exits the entire function (eval.rs: if let Some(v) = eval_block(then_body, …)?).
Note: Both the then and else blocks execute in a child scope. The evaluator calls env.push_scope() before entering either branch and env.pop_scope() after it completes (eval.rs: Stmt::If). Variables declared with let inside a branch are not visible outside that branch. To update a variable from an enclosing scope inside a branch, use bare assignment: x = new_value.

while Loops

The while statement is Jade's iteration construct. It evaluates a bool condition before each iteration and executes the loop body as long as the condition is true. Loop termination is controlled entirely by changing the values that the condition expression tests — typically by using bare assignment (i = i + 1) to update a variable that was declared before the loop.

Bare assignment (x = expr) updates an existing variable in the nearest enclosing scope that contains it. This is the standard way to advance a loop counter. Each iteration writes the new value back into the variable, and the loop condition tests that updated value on the next check.

A return statement inside a while body exits the enclosing function immediately, propagating the return value upward. A loop whose condition is always true and contains no return will run forever.

while Syntax

while <condition> {
    <body statements>
}
  • <condition> — any expression that produces a bool. Evaluated before each iteration, including the first.
  • <body statements> — any sequence of statements to execute while the condition is true. Typically includes a bare assignment to advance the loop variable, such as i = i + 1.
Note: The condition and the opening { must be on the same line. Because the lexer inserts a semicolon after any line ending in an integer, float, identifier, true, false, or ) token, writing the condition and brace on separate lines would insert an unexpected semicolon. Write while i < 5 { on one line.

while Examples

Counting up to a limit

let i = 0
while i < 5 {
    i = i + 1
}

Bare assignment updates i on each iteration. When i reaches 5, the condition i < 5 becomes false and the loop exits. After the loop, i holds 5.

Accumulating a sum

let n = 10
let sum = 0
let i = 1
while i <= n {
    sum = sum + i
    i = i + 1
}

Each iteration adds the current i to sum, then advances i. After the loop, sum holds 55 (the sum of integers 1 through 10).

Condition false from the start

let never = 99
while never < 0 {
    never = never + 1
}

The condition is false on the first check, so the body never executes. never remains 99.

While inside a function

fn sum_to(n) {
    let total = 0
    let i = 1
    while i <= n {
        total = total + i
        i = i + 1
    }
    return total
}

let s10 = sum_to(10)

A while loop can appear inside a function body. sum_to(10) iterates from 1 to 10, accumulating the sum, and returns 55.

while Advanced Examples

Iterative factorial — while as an alternative to recursion

fn factorial(n) {
    let result = 1
    let i = 1
    while i <= n {
        result = result * i
        i = i + 1
    }
    return result
}

let f5 = factorial(5)

Iterative and recursive implementations produce the same result. factorial(5) returns 120. The while loop multiplies result by each value of i from 1 to n, then the function returns the accumulated product.

Nested while loops

let total = 0
let i = 0
while i < 3 {
    let j = 0
    while j < 3 {
        total = total + 1
        j = j + 1
    }
    i = i + 1
}

The inner loop runs to completion on each iteration of the outer loop. After both loops finish, total holds 9 (three outer iterations, each running three inner iterations). j is declared fresh with let at the start of each outer iteration and updated with bare assignment inside the inner loop.

while Interaction with Other Features

  • Functions: while loops appear inside function bodies. A return inside the loop body exits the enclosing function immediately, propagating the return value. See Functions.
  • if/else inside while: An if/else statement can appear inside a loop body to vary behavior across iterations. A return inside such an if still exits the enclosing function.
  • Comparison operators: The most common source of bool conditions for while loops is comparison expressions: i < n, val <= 100, etc. See Operators.
  • Variable assignment: Jade uses bare assignment (i = i + 1) to advance loop variables. The variable must be declared with let before the loop; bare assignment then updates it in place through the scope chain. The condition tests the updated value on the next iteration. See Variables.

while Implementation Notes

Note: The while loop body executes in a child scope. The evaluator calls env.push_scope() before each iteration and env.pop_scope() after it (eval.rs: Stmt::While). Variables declared with let inside the loop body are local to that iteration and are not visible outside the loop or in subsequent iterations. To update a variable across iterations, declare it with let before the loop and use bare assignment (i = i + 1) inside the body, which traverses the scope chain and updates the binding in the enclosing scope.
Note: The condition and the opening { must be on the same source line. The lexer inserts a semicolon when a line ends in an integer, float, identifier, boolean literal, ), or } token. A condition ending in any of those token kinds, followed by a newline before {, would cause a parse error. Write the condition and brace on one line: while i < 5 { (lexer.rs: is_line_terminator).
Note: A return inside the loop body is detected when eval_block returns Some(value). The while handler checks for this after each iteration and propagates it immediately, stopping the loop and returning the value to the caller (eval.rs: if let Some(v) = eval_block(body, Rc::clone(&env))? { return Ok(Some(v)); }).
