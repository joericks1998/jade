Control Flow

Jade's if/else statement conditionally executes one of two blocks of code based on a bool condition.

Overview

The if statement is Jade's sole branching construct in version 1.0.3. It tests a condition expression and executes the then block when the condition is true. An optional else block executes when the condition is false. If no else is provided and the condition is false, the statement does nothing.

The condition must evaluate to a bool value. Providing any other type — an int, float, or fn value — raises a TypeError. There is no implicit truthiness for non-boolean types.

Control flow statements appear inside function bodies. An if statement at the top level is also valid, but a return inside such an if would trigger a ReturnOutsideFunction error because return is only legal inside a function body.

Syntax

if without else

if <condition> {
    <then statements>
}

if with else

if <condition> {
    <then statements>
} else {
    <else statements>
}
  • <condition> — any expression that produces a bool. Common sources: comparison operators (<, >, ==, etc.), logical operators (&&, ||, !), or a variable holding a bool value.
  • <then statements> — any sequence of statements to execute when the condition is true.
  • <else statements> — any sequence of statements to execute when the condition is false. May itself contain if/else to create chains.
Note: The else keyword must appear on the same line as the closing } of the then block, or on the next line. Because the lexer does not insert a semicolon after }, writing } else { on one line or splitting across lines both work correctly.

Basic Examples

Returning different values based on a condition

fn max(a, b) {
    if a > b {
        return a
    } else {
        return b
    }
}

let m1 = max(3, 7)
let m2 = max(10, 2)

max compares a and b and returns the larger. max(3, 7) takes the else branch and returns 7. max(10, 2) takes the if branch and returns 10.

if without else — early return pattern

fn clamp(x, lo, hi) {
    if x < lo {
        return lo
    }
    if x > hi {
        return hi
    }
    return x
}

let clamped_lo  = clamp(1, 5, 10)
let clamped_mid = clamp(7, 5, 10)
let clamped_hi  = clamp(15, 5, 10)

Multiple if statements without else create an early-exit chain. clamp(1, 5, 10) hits the first condition and returns 5. clamp(7, 5, 10) skips both conditions and falls through to return x, returning 7. clamp(15, 5, 10) hits the second condition and returns 10.

Boolean variable as condition

fn is_positive(x) {
    if x > 0 {
        return true
    } else {
        return false
    }
}

let pos = is_positive(5)
let neg = is_positive(-3)

The condition can be any expression that produces a bool. Here x > 0 evaluates to true or false, which the if statement tests. is_positive(5) returns true; is_positive(-3) returns false.

Advanced Examples

Nested if/else — sign function

fn sign(x) {
    if x > 0 {
        return 1
    } else {
        if x < 0 {
            return -1
        } else {
            return 0
        }
    }
}

let s1 = sign(10)
let s2 = sign(-5)
let s3 = sign(0)

The else branch itself contains another if/else, creating a three-way branch. sign(10) returns 1, sign(-5) returns -1, and sign(0) returns 0. Nesting depth is not bounded by the language.

Nested if — quadrant classification

fn quadrant(a, b) {
    if a > 0 {
        if b > 0 {
            return 1
        } else {
            return 4
        }
    } else {
        if b > 0 {
            return 2
        } else {
            return 3
        }
    }
}

let q1 = quadrant(1, 1)
let q2 = quadrant(-1, 1)
let q3 = quadrant(-1, -1)
let q4 = quadrant(1, -1)

Both the then and else branches contain their own if/else to inspect a second variable. quadrant(1, 1) returns 1 (positive a, positive b). quadrant(-1, 1) returns 2, and so on.

Type Rules

OperationCondition TypeResultNotes
if <cond> — condition is true bool Then block executes eval.rs:eval_block, Value::Bool(true) arm
if <cond> — condition is false bool Else block executes (if present) eval.rs:eval_block, Value::Bool(false) arm
if <cond> — condition is not a bool int, float, or fn TypeError eval.rs: _ => Err(JadeError::TypeError { op: "if".to_string(), … })
return inside a branch Any Propagates return value up to enclosing function eval.rs: if let Some(v) = eval_block(then_body, …)?
Note: The condition must be exactly a bool. There is no implicit truthiness: if 1 { … } is a TypeError, not a truthy integer check.

Error Conditions

ErrorTriggerExample
TypeError Condition is not a bool fn f(x) { if x { return 1 } return 0 } called as f(5)
ReturnOutsideFunction return inside a top-level if if true { return 1 } at the top level
UndefinedVariable Referencing an undeclared name inside a branch fn f() { if true { return z } } where z is not defined

Interaction with Other Features

  • Functions: if/else is typically used inside function bodies. A return inside a branch exits the entire enclosing function, not just the branch. See Functions.
  • Logical operators: The condition can use &&, ||, and ! to combine multiple boolean sub-expressions. All operands must be bool. See Operators.
  • Comparison operators: The most common source of bool conditions is comparison expressions: x > 0, a == b, n <= 1, etc. These produce bool values that the if statement can test directly.
  • Variable bindings: A let statement inside a branch creates a binding in the enclosing function's scope, not a new nested scope. Both the then and else blocks share the same environment frame as the surrounding function body.
  • Recursion: if/else is the standard way to express base cases in recursive functions. The condition tests for the stopping condition and the return inside exits the recursion at that call.

Implementation Notes

Note: Auto-semicolon insertion does not insert a semicolon after a closing }. This is what allows } else { to parse correctly across lines — the lexer intentionally excludes RBrace from the set of tokens that trigger semicolon insertion (lexer.rs: is_line_terminator).
Note: A return statement inside either the then or else block propagates upward through the block evaluator using Rust's Option<Value> return type. When eval_block returns Some(value), the caller propagates it immediately without executing any further statements in the enclosing block. This is how a return deep inside a branch exits the entire function (eval.rs: if let Some(v) = eval_block(then_body, …)?).
Note: The then and else blocks share the same Env frame as the surrounding block — the evaluator passes Rc::clone(&env) into both branches rather than creating a new child frame. Variables declared with let inside a branch are visible after the branch completes, within the same function body (eval.rs: eval_block(then_body, Rc::clone(&env))).
