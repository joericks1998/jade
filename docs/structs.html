Structs

Structs are named record types that group related values under named fields. Methods can be attached to any struct type using extend blocks.

Overview

A struct definition introduces a new named type with an ordered list of field names. Once defined, a struct type can be instantiated by providing values for every field in a struct literal. The resulting value is a struct instance that holds those field values and can be stored in a variable.

Individual fields are read with dot syntax (obj.field) and updated with field assignment syntax (obj.field = expr). Field assignment mutates the existing instance in place — all variables that hold a reference to the same instance see the updated value immediately.

Methods are defined separately from the struct using an extend block. Each method receives the instance it was called on as its first parameter, conventionally named self. Calling a method through dot syntax (obj.method(args)) automatically supplies the instance as self; the caller does not pass it explicitly.

Syntax

Struct Definition

struct <TypeName> {
    <field>,
    <field>,
    ...
}
  • <TypeName> — an identifier naming the type; registered in the global struct registry.
  • <field> — one or more field names separated by commas. Fields have no type annotation — they hold any Value at runtime.

Struct Instantiation (Struct Literal)

<TypeName> { <field>: <expr>, <field>: <expr>, ... }
  • Every field declared in the struct definition must be present in the literal.
  • Extra fields not declared in the definition raise an UndefinedField error.
  • Missing fields raise a MissingField error.
  • The struct type must have been defined before the literal is evaluated.

Field Access

<expr>.<field>
  • Evaluates <expr> to a struct instance, then returns the value of the named field.
  • If the named field does not exist on the instance, raises UndefinedField.
  • If <expr> does not evaluate to a struct, raises NotAStruct.

Field Assignment

<variable>.<field> = <expr>
  • Updates the named field on the struct instance held by <variable>.
  • The left-hand side must be a plain variable name — chained assignment such as a.b.c = x is not supported.
  • The field must already exist on the instance; attempting to assign to an undeclared field raises UndefinedField.

Extend Block

extend <TypeName> {
    fn <method>(self, <param>, ...) {
        <body>
        return <expr>
    }
    ...
}
  • <TypeName> — the struct type to attach methods to. The type must be defined before or in the same program.
  • Each method is a fn definition where the first parameter receives the receiver instance. Conventionally named self.
  • Methods that do not need to read or mutate the instance may omit self.

Method Call

<expr>.<method>(<arg>, ...)
  • Field access on a struct first checks instance fields, then checks the method table for the struct type.
  • When a method is found, a bound method value is returned. Calling it automatically passes the receiver as the first argument (self).
  • The caller supplies only the arguments after self.

Basic Examples

Defining a struct and accessing its fields

struct Point {
    x,
    y
}

let p = Point { x: 10, y: 20 }
let px = p.x
let py = p.y

struct Point declares a type with two fields, x and y. The literal Point { x: 10, y: 20 } creates an instance and binds it to p. p.x evaluates to 10 and p.y evaluates to 20.

Mutating a field with field assignment

struct Point {
    x,
    y
}

let p = Point { x: 10, y: 20 }
p.x = 99
let updated_x = p.x

p.x = 99 overwrites the x field on the existing instance. After the assignment, p.x evaluates to 99. The instance is mutated in place — the variable p still refers to the same struct object.

Attaching a method with extend and calling it

struct Counter {
    count
}

extend Counter {
    fn increment(self) {
        self.count = self.count + 1
    }
    fn value(self) {
        return self.count
    }
}

let c = Counter { count: 0 }
c.increment()
c.increment()
let v = c.value()

The extend Counter block adds two methods. increment mutates the count field through self. value returns the current count. After two calls to c.increment(), c.value() returns 2. Mutations through self inside a method are visible on the original instance because self and the caller's variable share the same underlying struct object.

Advanced Examples

Multiple struct types in one program

struct Point {
    x,
    y
}

struct Counter {
    count
}

let p = Point { x: 3, y: 4 }
let c = Counter { count: 0 }

extend Counter {
    fn increment(self) {
        self.count = self.count + 1
    }
}

c.increment()
c.increment()
c.increment()
let total = c.count

Multiple struct types can coexist in the same program. Each extend block targets exactly one type by name. total holds 3 after three calls to c.increment().

Method that uses a parameter alongside self

struct Accumulator {
    total
}

extend Accumulator {
    fn add(self, n) {
        self.total = self.total + n
    }
    fn result(self) {
        return self.total
    }
}

let acc = Accumulator { total: 0 }
acc.add(10)
acc.add(5)
acc.add(3)
let sum = acc.result()

add takes self and an extra parameter n. When called as acc.add(10), the evaluator binds self to the receiver and n to 10. After three calls, acc.result() returns 18.

Type Rules

OperationOperand TypesResult TypeNotes
Struct literal T { field: expr } All field expressions evaluated in current scope Struct instance eval.rs: Expr::StructLiteral
Field access obj.field obj is a struct instance; field is a declared field name Whatever value is stored in the field eval.rs: Expr::FieldAccess, instance fields checked first
Method access obj.method obj is a struct instance; method is defined in an extend block BoundMethod value eval.rs: Expr::FieldAccess, method table checked after fields
Method call obj.method(args) BoundMethod; caller supplies args after self Whatever the method returns, or 0 if no return eval.rs: Expr::Call on Value::BoundMethod
Field assignment obj.field = expr obj holds a struct instance; field is a declared field No return value (statement only) eval.rs: Stmt::FieldAssign
Field access on non-struct Any non-struct value NotAStruct error eval.rs: Expr::FieldAccess, wildcard arm
Note: Struct fields hold any runtime value — int, float, bool, another Struct, or a fn value. There are no field type annotations and no static type checking on field values.

Error Conditions

ErrorTriggerExample
UndefinedType Struct literal uses a type name that has not been defined let p = Foo { x: 1 } when no struct Foo exists
MissingField Struct literal omits a required field struct Point { x, y } then let p = Point { x: 1 }
UndefinedField Struct literal includes a field not declared in the struct, or dot access/assignment targets an undeclared field struct Point { x, y } then let p = Point { x: 1, y: 2, z: 3 }
NotAStruct Dot access or field assignment on a non-struct value let x = 5 then let y = x.foo
ArityMismatch Method called with the wrong number of arguments (not counting self) extend Counter { fn add(self, n) { … } } then c.add(1, 2)
Note: The arity check for method calls excludes self from the expected count — self is supplied automatically by the evaluator. A method defined as fn add(self, n) expects exactly one argument from the caller (eval.rs: Value::BoundMethod arm of Expr::Call).

Interaction with Other Features

  • Variable assignment: Field mutation (obj.field = expr) is a separate statement form from bare variable assignment (x = expr). Both update existing state without creating new bindings. See Variables.
  • Functions: Struct instances can be passed as function arguments and returned from functions. Because instances are shared via reference, mutations inside a called function are visible in the caller. Methods defined in extend blocks are regular fn definitions attached to a type's method table. See Functions.
  • Control flow: if/else and while can appear inside method bodies. A return inside a method exits the method and produces its return value. See Control Flow.
  • Type rules: Struct fields can hold any value type — int, float, bool, or even another struct instance. Arithmetic operators and comparison operators applied to field values follow the same promotion and coercion rules as any other expression. See Types.
  • Verbose output: When running with --verbose, struct instances at the global scope are printed as name = TypeName { field: value, … }, with fields sorted alphabetically. See CLI Reference.

Implementation Notes

Note: Struct definitions are stored in a global registry (env.struct_defs), not in the scope chain. This means a struct definition is visible everywhere in the program regardless of where it appears, but nested struct definitions inside function bodies are still parsed as top-level definitions because the struct keyword is only handled at the statement level (eval.rs: Stmt::StructDef).
Note: Struct instances are heap-allocated and shared via Rc<RefCell<StructInstance>>. Assigning a struct instance to a new variable does not copy it — both variables reference the same object. A field mutation through one variable is immediately visible through the other (eval.rs: Value::Struct(Rc<RefCell<StructInstance>>)).
Note: Method lookup in field access first checks instance fields, then the method table for the struct type. If an instance field and a method have the same name, the instance field wins (eval.rs: Expr::FieldAccess). To avoid ambiguity, use distinct names for fields and methods.
Note: Struct literals are disallowed in if and while conditions. The parser sets struct_literal_allowed = false while parsing a condition so that while running { … } does not try to interpret running {…} as a struct literal (parser.rs: parse_condition).
Note: The lexer inserts a semicolon after } at the end of a line. This means a struct literal on its own line terminates the statement correctly, but a struct literal whose closing } is followed by another expression on the same line must be parenthesized to avoid ambiguity (lexer.rs: is_line_terminator includes RBrace).
